## 1.4 필드 가시성 관리

### 설계 원칙

**권한 기준:**
- **RoleCategory 기반** + **SUPER_ADMIN 예외** (고정, 수정 불가)
- **RoleGroup으로 확장/제한** (VIP 추가 허용, BLACKLIST 제한)

**열 구성:**
- 관리자 계열: RoleGroup 구분 없음 (직원은 보통 등급 구분 없음)
- 사용자 계열: NORMAL, VIP, BLACKLIST 구분

**가시성 옵션:**
- ✅ 전체 공개
- ⚠️ 부분 마스킹
- ❌ 숨김 (필드 제외)

### 필드 타입별 기본 마스킹 패턴

| 필드 타입 | 기본 패턴 | 예시 |

| 전화번호 | 중간 4자리 마스킹 | `010-****-9012` |
| 주민번호 | 뒷자리 전체 마스킹 | `920315-1******` |
| 계좌번호 | 중간 마스킹 | `110-***-***456` |
| 주소 | 상세주소 마스킹 | `서울시 강남구 ***` |
| 이름 | 중간 글자 마스킹 | `김*수` |
| 카드번호 | 중간 8자리 마스킹 | `1234-****-****-5678` |

### RoleGroup별 동작 설명

| RoleGroup | 동작 | 설명 |
|-----------|------|------|
| NORMAL | 기본값 | RoleCategory 설정 그대로 적용 |
| VIP | 확장 | 추가 필드 접근 허용 (premiumReport, trainerContact 등) |
| BLACKLIST | 제한 | 민감 필드 접근 제한 (paymentHistory, internalMemo 등) |

> **Action 기반 구현 (2026-01-10)**
> 위 필드 가시성 매트릭스는 Ability + Action 조합으로 구현됩니다.
> - `read` Action → 전체 조회 (✅)
> - `read:masked:email` Action → 이메일 마스킹 (⚠️)
> - `read:hidden` Action → 숨김 (❌)
