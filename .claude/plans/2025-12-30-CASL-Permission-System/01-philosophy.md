## 1. RBAC과 ABAC의 역할 분리

```
┌─────────────────────────────────────────────────────────────────────┐
│                         권한 시스템 구조                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   RBAC (Role-Based Access Control)                                  │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  • 메뉴 접근 권한                                            │   │
│   │  • API 엔드포인트 접근                                       │   │
│   │  • 기능 ON/OFF                                               │   │
│   │  → 기존 Role, RoleCategory, RoleGroup 시스템 유지            │   │
│   │  → @RoleCategories, @RoleGroups 데코레이터 사용              │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                              │                                       │
│                              ▼                                       │
│   ABAC (Attribute-Based Access Control) - CASL                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  • 데이터 레벨 필터링 (본인 데이터만, 부서 데이터만)           │   │
│   │  • 필드 가시성 제어 (이메일, 전화번호 마스킹)                  │   │
│   │  • 조건부 권한 (상태, 기간, 소유권 기반)                      │   │
│   │  → Role 기반 기본 권한 + User 기반 예외 권한                  │   │
│   │  → CASL 라이브러리 컨벤션 준수                               │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. ABAC 권한 구조: Role 기반 + User 예외

```
┌─────────────────────────────────────────────────────────────────┐
│                        Ability 모델                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   1. Role 연결 (기본 권한)                                        │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  ADMIN Role → "모든 예약 조회", "사용자 관리"              │   │
│   │  USER Role  → "본인 예약만", "본인 정보만"                 │   │
│   │  → 역할별 기본 ABAC 규칙 정의                             │   │
│   │  → 신규 사용자는 Role 지정만으로 권한 상속                 │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              +                                   │
│   2. User 연결 (개별 예외)                                        │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  홍길동 → "HR 부서 데이터 추가 접근" (예외 허용)           │   │
│   │  김철수 → "삭제 권한 제거" (예외 제한)                    │   │
│   │  → 특정 사용자만 추가/제한 필요할 때 사용                  │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              ↓                                   │
│   3. 병합하여 최종 CASL Ability 생성                              │
│      (User 규칙이 Role 규칙보다 우선)                             │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 제어 대상 분류

| 구분 | 제어 방식 | Subject 패턴 | 예시 | 결정 시점 |
|------|----------|-------------|------|----------|
| 메뉴 접근 | **RBAC** | `menu:xxx` | 설정 메뉴 보이기/숨기기 | 라우팅 레벨 |
| API 엔드포인트 | **RBAC** | API | POST /users 호출 가능 여부 | 가드 레벨 |
| 기능 버튼 | **RBAC** | `feature:xxx` | 내보내기 버튼 활성화 | UI 렌더링 |
| 데이터 범위 | **ABAC** | `entity:xxx` | 본인 예약만 조회 | 쿼리 레벨 |
| **필드 가시성** | **ABAC** | `entity:xxx` | 전화번호 마스킹 (read:masked:phone) | 응답 레벨 |
| **UI 요소** | **ABAC** | **`ui:xxx`** | 모바일 바텀탭, 메인 배너 가시성 | UI 렌더링 |
| 조건부 수정 | **ABAC** | `entity:xxx` | 대기 상태만 수정 가능 | 비즈니스 로직 |

> **핵심 변경 (2026-01-10):**
> 1. **Action 모델 도입**: Action이 `config: Json?` 필드를 통해 마스킹, 포맷팅, 변환 등 완전한 정의를 가짐 (DDD 원칙)
> 2. **FieldVisibility/MaskingPattern 제거**: Ability + Action으로 통합 (예: `read:masked:email` Action 사용)
> 3. **UI Subject 패턴 추가**: `ui:xxx` 패턴으로 특정 화면 요소의 가시성 제어

### Subject 패턴 체계

| 패턴 | 예시 | 용도 |
|------|------|------|
| `all` | `all` | 전체 권한 |
| `entity:xxx` | `entity:User`, `entity:Reservation` | 데이터 엔티티 |
| `menu:xxx` | `menu:settings`, `menu:dashboard` | 메뉴 접근 |
| `feature:xxx` | `feature:export`, `feature:bulk-delete` | 기능 접근 |
| **`ui:xxx`** | `ui:mobile-bottom-tab`, `ui:main-banner` | **UI 요소 가시성** |

### UI Subject 예시

| Subject | 설명 | Ability 예시 |
|---------|------|-------------|
| `ui:mobile-bottom-tab` | 모바일 바텀탭 전체 | `{ subject: 'ui:mobile-bottom-tab', action: 'access' }` |
| `ui:mobile-bottom-tab:home` | 바텀탭 - 홈 탭 | `{ subject: 'ui:mobile-bottom-tab:home', action: 'read:hidden', inverted: true }` |
| `ui:main-banner` | 메인 배너 | `{ subject: 'ui:main-banner', action: 'access', role: 'VIP' }` |
| `ui:sidebar-menu:admin` | 사이드바 관리자 메뉴 | `{ subject: 'ui:sidebar-menu:admin', action: 'access' }` |
| `ui:floating-button:chat` | 플로팅 채팅 버튼 | `{ subject: 'ui:floating-button:chat', action: 'access' }` |

## 4. Role vs RoleCategory vs RoleGroup 구분

### 왜 세 가지가 필요한가?

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Role / RoleCategory / RoleGroup 비교                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Role (시스템 권한 레벨)                                                       │
│  ├── 개수: 3개 고정 (USER, ADMIN, SUPER_ADMIN)                               │
│  ├── 목적: 시스템 전반의 권한 수준 결정                                         │
│  ├── 특징: 코드에 하드코딩, 변경 거의 없음                                      │
│  └── 예시: "이 API는 ADMIN 이상만 호출 가능"                                   │
│                                                                              │
│  RoleCategory (직군/직책 분류) ← Category 테이블, 계층 구조                     │
│  ├── 개수: 동적 확장 가능                                                     │
│  ├── 목적: 같은 Role 내에서 세부 권한 분리                                      │
│  ├── 특징: 트리 구조로 권한 상속 가능                                          │
│  └── 예시: "ADMIN 중에서도 TRAINER는 정산 메뉴 접근 불가"                       │
│                                                                              │
│  RoleGroup (횡단 그룹핑) ← Group 테이블                                        │
│  ├── 개수: 동적 확장 가능                                                     │
│  ├── 목적: 직군과 무관한 특별 혜택/제한 그룹                                    │
│  ├── 특징: 플랫 구조, 여러 Role/Category에 걸쳐 적용                           │
│  └── 예시: "VIP 그룹은 우선 예약권 + 전용 라운지 접근"                          │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### RoleCategory 계층 구조 (예약 서비스)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Category 트리 구조 (type: Role)                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  COMMON (공통 - 최상위)                                                       │
│  │                                                                           │
│  ├── ADMIN (관리자 계열)                                                      │
│  │   │                                                                       │
│  │   ├── MANAGER (점장)                                                      │
│  │   │   └── 지점 전체 관리, 직원 관리, 정산 확인                               │
│  │   │                                                                       │
│  │   ├── TRAINER (트레이너)                                                   │
│  │   │   └── 회원 관리, 세션/프로그램 운영, 예약 확인                            │
│  │   │                                                                       │
│  │   ├── FRONT_DESK (프론트 데스크)                                           │
│  │   │   └── 예약 접수/변경, 체크인, 고객 응대                                  │
│  │   │                                                                       │
│  │   └── ACCOUNTANT (정산 담당)                                               │
│  │       └── 정산 관리, 매출 리포트, 환불 처리                                  │
│  │                                                                           │
│  └── USER (사용자 계열)                                                       │
│      │                                                                       │
│      ├── MEMBER (일반 회원)                                                   │
│      │   └── 예약, 본인 정보 관리                                              │
│      │                                                                       │
│      └── GUEST (게스트)                                                       │
│          └── 체험권 예약만 가능                                                │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

권한 상속 예시:
- @RoleCategories([ADMIN]) 요구 시
  → ADMIN, MANAGER, TRAINER, FRONT_DESK, ACCOUNTANT 모두 접근 가능

- @RoleCategories([TRAINER]) 요구 시
  → TRAINER만 접근 가능 (MANAGER는 접근 불가)

- @RoleCategories([COMMON]) 요구 시
  → 모든 카테고리 접근 가능 (최상위이므로)
```
