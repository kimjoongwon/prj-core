## 0. 설계 철학

### 0.1 RBAC과 ABAC의 역할 분리

```
┌─────────────────────────────────────────────────────────────────────┐
│                         권한 시스템 구조                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   RBAC (Role-Based Access Control)                                  │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  • 메뉴 접근 권한                                            │   │
│   │  • API 엔드포인트 접근                                       │   │
│   │  • 기능 ON/OFF                                               │   │
│   │  → 기존 Role, RoleCategory, RoleGroup 시스템 유지            │   │
│   │  → @RoleCategories, @RoleGroups 데코레이터 사용              │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                              │                                       │
│                              ▼                                       │
│   ABAC (Attribute-Based Access Control) - CASL                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  • 데이터 레벨 필터링 (본인 데이터만, 부서 데이터만)           │   │
│   │  • 필드 가시성 제어 (이메일, 전화번호 마스킹)                  │   │
│   │  • 조건부 권한 (상태, 기간, 소유권 기반)                      │   │
│   │  → Role 기반 기본 권한 + User 기반 예외 권한                  │   │
│   │  → CASL 라이브러리 컨벤션 준수                               │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 0.2 ABAC 권한 구조: Role 기반 + User 예외

```
┌─────────────────────────────────────────────────────────────────┐
│                        Ability 모델                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   1. Role 연결 (기본 권한)                                        │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  ADMIN Role → "모든 예약 조회", "사용자 관리"              │   │
│   │  USER Role  → "본인 예약만", "본인 정보만"                 │   │
│   │  → 역할별 기본 ABAC 규칙 정의                             │   │
│   │  → 신규 사용자는 Role 지정만으로 권한 상속                 │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              +                                   │
│   2. User 연결 (개별 예외)                                        │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  홍길동 → "HR 부서 데이터 추가 접근" (예외 허용)           │   │
│   │  김철수 → "삭제 권한 제거" (예외 제한)                    │   │
│   │  → 특정 사용자만 추가/제한 필요할 때 사용                  │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              ↓                                   │
│   3. 병합하여 최종 CASL Ability 생성                              │
│      (User 규칙이 Role 규칙보다 우선)                             │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 0.3 제어 대상 분류

| 구분 | 제어 방식 | Subject 타입 | 예시 | 결정 시점 |
|------|----------|-------------|------|----------|
| 메뉴 접근 | **RBAC** | Menu | 설정 메뉴 보이기/숨기기 | 라우팅 레벨 |
| API 엔드포인트 | **RBAC** | API | POST /users 호출 가능 여부 | 가드 레벨 |
| 기능 버튼 | **RBAC** | Feature | 내보내기 버튼 활성화 | UI 렌더링 |
| 데이터 범위 | **ABAC** | Entity | 본인 예약만 조회 | 쿼리 레벨 |
| **필드 가시성** | **ABAC** | **Column** | 전화번호 마스킹 | 응답 레벨 |
| 조건부 수정 | **ABAC** | Entity | 대기 상태만 수정 가능 | 비즈니스 로직 |

> **핵심 변경**: 필드 가시성은 UIConfig 없이 **Column Subject + READ 액션**으로 제어합니다.
> Column Subject는 Prisma 스키마에서 `@displayName` 주석이 있는 필드에서 자동 생성됩니다.

### 0.4 Role vs RoleCategory vs RoleGroup 구분

#### 왜 세 가지가 필요한가?

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Role / RoleCategory / RoleGroup 비교                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Role (시스템 권한 레벨)                                                       │
│  ├── 개수: 3개 고정 (USER, ADMIN, SUPER_ADMIN)                               │
│  ├── 목적: 시스템 전반의 권한 수준 결정                                         │
│  ├── 특징: 코드에 하드코딩, 변경 거의 없음                                      │
│  └── 예시: "이 API는 ADMIN 이상만 호출 가능"                                   │
│                                                                              │
│  RoleCategory (직군/직책 분류) ← Category 테이블, 계층 구조                     │
│  ├── 개수: 동적 확장 가능                                                     │
│  ├── 목적: 같은 Role 내에서 세부 권한 분리                                      │
│  ├── 특징: 트리 구조로 권한 상속 가능                                          │
│  └── 예시: "ADMIN 중에서도 TRAINER는 정산 메뉴 접근 불가"                       │
│                                                                              │
│  RoleGroup (횡단 그룹핑) ← Group 테이블                                        │
│  ├── 개수: 동적 확장 가능                                                     │
│  ├── 목적: 직군과 무관한 특별 혜택/제한 그룹                                    │
│  ├── 특징: 플랫 구조, 여러 Role/Category에 걸쳐 적용                           │
│  └── 예시: "VIP 그룹은 우선 예약권 + 전용 라운지 접근"                          │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### RoleCategory 계층 구조 (예약 서비스)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Category 트리 구조 (type: Role)                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  COMMON (공통 - 최상위)                                                       │
│  │                                                                           │
│  ├── ADMIN (관리자 계열)                                                      │
│  │   │                                                                       │
│  │   ├── MANAGER (점장)                                                      │
│  │   │   └── 지점 전체 관리, 직원 관리, 정산 확인                               │
│  │   │                                                                       │
│  │   ├── TRAINER (트레이너)                                                   │
│  │   │   └── 회원 관리, 세션/프로그램 운영, 예약 확인                            │
│  │   │                                                                       │
│  │   ├── FRONT_DESK (프론트 데스크)                                           │
│  │   │   └── 예약 접수/변경, 체크인, 고객 응대                                  │
│  │   │                                                                       │
│  │   └── ACCOUNTANT (정산 담당)                                               │
│  │       └── 정산 관리, 매출 리포트, 환불 처리                                  │
│  │                                                                           │
│  └── USER (사용자 계열)                                                       │
│      │                                                                       │
│      ├── MEMBER (일반 회원)                                                   │
│      │   └── 예약, 본인 정보 관리                                              │
│      │                                                                       │
│      └── GUEST (게스트)                                                       │
│          └── 체험권 예약만 가능                                                │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

권한 상속 예시:
- @RoleCategories([ADMIN]) 요구 시
  → ADMIN, MANAGER, TRAINER, FRONT_DESK, ACCOUNTANT 모두 접근 가능

- @RoleCategories([TRAINER]) 요구 시
  → TRAINER만 접근 가능 (MANAGER는 접근 불가)

- @RoleCategories([COMMON]) 요구 시
  → 모든 카테고리 접근 가능 (최상위이므로)
```

#### 시나리오 1: 메뉴 접근 권한 (RBAC - RoleCategory 기반)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    직군별 메뉴 접근 권한 매트릭스                               │

│  ────────────────────┼───────┼─────────┼─────────┼───────┼─────────┼─────────│
│  📊 대시보드          │  ✅   │   ✅    │   ✅    │  ✅   │   ✅    │ ADMIN   │

│    ├ 예약 접수/변경   │  ✅   │   ✅    │   ✅    │  ✅   │   ❌    │ FRONT   │
│    └ 프로그램 편성    │  ✅   │   ✅    │   ✅    │  ❌   │   ❌    │ TRAINER │
│  💰 정산 관리         │  ✅   │   ✅    │   ❌    │  ❌   │   ✅    │ 특수    │
│    ├ 매출 리포트      │  ✅   │   ✅    │   ❌    │  ❌   │   ✅    │ MANAGER │
│    └ 환불 처리        │  ✅   │   ✅    │   ❌    │  ❌   │   ✅    │ +ACCOUNT│
│  ⚙️ 설정             │  ✅   │   ⚠️    │   ❌    │  ❌   │   ❌    │ 제한적  │
│    ├ 시설 정보        │  ✅   │   ✅    │   ❌    │  ❌   │   ❌    │ MANAGER │
│    ├ 권한 관리        │  ✅   │   ❌    │   ❌    │  ❌   │   ❌    │ SUPER만 │
│    └ 시스템 설정      │  ✅   │   ❌    │   ❌    │  ❌   │   ❌    │ SUPER만 │
│                                                                              │
│  ⚠️ = 일부 기능만 접근 가능                                                    │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

Guard 데코레이터 예시:

@RoleCategories([ADMIN])           // 모든 관리자 접근 (MANAGER, TRAINER, FRONT_DESK, ACCOUNTANT)
@RoleCategories([TRAINER])         // 트레이너만 접근 (회원 정보 수정, 세션 운영)
@RoleCategories([MANAGER])         // 점장만 접근 (직원 관리, 정산)
@RoleCategories([MANAGER, ACCOUNTANT])  // 점장 또는 정산담당 (환불 처리)
```

#### 3.6.5 백엔드 구현 - FieldVisibilityInterceptor

```typescript
// packages/be-common/src/interceptors/field-visibility.interceptor.ts

@Injectable()
export class FieldVisibilityInterceptor implements NestInterceptor {
  constructor(
    private readonly abilitiesRepository: AbilitiesRepository,
    private readonly subjectsRepository: SubjectsRepository,
  ) {}

  async intercept(context: ExecutionContext, next: CallHandler): Promise<Observable<any>> {
    const request = context.switchToHttp().getRequest();
    const user = request.user;

    return next.handle().pipe(
      map(async (data) => {
        if (!user || !data) return data;

        // Entity 추출 (Swagger 메타데이터 또는 명시적 지정)
        const entityName = this.extractEntityName(context);
        if (!entityName) return data;

        // Column Abilities 조회
        const columnAbilities = await this.getColumnAbilities(user.roleId, entityName);

        // 필드 필터링/마스킹 적용
        return this.filterFields(data, columnAbilities);
      }),
    );
  }

  private async getColumnAbilities(roleId: string, entityName: string) {
    // 1. Entity Subject 조회
    const entitySubject = await this.subjectsRepository.findByName(`entity:${entityName}`);

    // 2. Role의 Entity/Column Abilities 조회
    const abilities = await this.abilitiesRepository.findByRoleAndSubjectType(
      roleId,
      ['Entity', 'Column'],
    );

    return abilities.filter(a =>
      a.subject.name === `entity:${entityName}` ||
      a.subject.name.startsWith(`column:${entityName}.`)
    );
  }

  private filterFields(data: any, abilities: Ability[]): any {
    const result = { ...data };

    for (const [field, value] of Object.entries(result)) {
      const columnAbility = abilities.find(a =>
        a.subject.name === `column:${data.constructor.name}.${field}`
      );

      // CAN_NOT이면 필드 제거
      if (columnAbility?.type === AbilityTypes.CAN_NOT) {
        delete result[field];
        continue;
      }

      // 마스킹 조건이 있으면 적용
      if (columnAbility?.conditions?.mask) {
        result[field] = this.applyMask(value, columnAbility.conditions);
      }
    }

    return result;
  }

  private applyMask(value: any, conditions: { mask: string; pattern: string }): string {
    if (conditions.pattern === 'email') {
      return value.replace(/(.{3}).*@/, '$1***@');
    }
    if (conditions.pattern === 'phone') {
      return value.replace(/(\d{3})-\d{4}-(\d{4})/, '$1-****-$2');
    }
    return '***';
  }
}
```

#### 3.6.6 프론트엔드 구현 - useColumnAbility

```typescript
// packages/hook/src/casl/useColumnAbility.ts

/**
 * Column Subject 기반 필드 가시성 확인 훅
 *
 * @example
 * const canReadEmail = useColumnAbility('User', 'email');
 * const canReadPhone = useColumnAbility('User', 'phone');
 */
export function useColumnAbility(entity: string, field: string): boolean {
  const ability = useAbility();
  return ability.can('read', `column:${entity}.${field}`);
}

/**
 * Entity의 모든 필드 가시성을 한번에 확인
 *
 * @example
 * const fieldVisibility = useEntityFieldVisibility('User');
 * // { email: true, phone: true, ssn: false, internalMemo: false }
 */
export function useEntityFieldVisibility(entity: string): Record<string, boolean> {
  const ability = useAbility();
  const { data: columns } = useGetColumnSubjects(entity);

  const visibility: Record<string, boolean> = {};

  for (const column of columns ?? []) {
    const fieldName = column.name.replace(`column:${entity}.`, '');
    visibility[fieldName] = ability.can('read', column.name);
  }

  return visibility;
}
```

```typescript
  action: 'access' | 'read' | 'create' | 'update' | 'delete' | 'manage',
  subject: string
): boolean {
  const ability = useAbility();
  return ability.can(action, subject);
}

// ─────────────────────────────────────────────────────────────
// 타입별 편의 훅
// ─────────────────────────────────────────────────────────────

/**
 * 메뉴 접근 권한
 * @example useMenuAbility('dashboard') → menu:dashboard ACCESS 체크
 */
export function useMenuAbility(menuPath: string): boolean {
  return useSubjectAbility('access', `menu:${menuPath}`);
}

/**
 * 기능 사용 권한
 * @example useFeatureAbility('export') → feature:export ACCESS 체크
 */
export function useFeatureAbility(featureName: string): boolean {
  return useSubjectAbility('access', `feature:${featureName}`);
}

/**
 * 엔티티 CRUD 권한
 * @example useEntityAbility('User') → entity:User 권한 객체
 */
export function useEntityAbility(entityName: string) {
  const ability = useAbility();
  const subject = `entity:${entityName}`;

  return {
    canCreate: ability.can('create', subject),
    canRead: ability.can('read', subject),
    canUpdate: ability.can('update', subject),
    canDelete: ability.can('delete', subject),
    canManage: ability.can('manage', subject),
  };
}

/**
 * 컬럼 가시성 권한
 * @example useColumnAbility('User', 'email') → column:User.email READ 체크
 */
export function useColumnAbility(entityName: string, fieldName: string): boolean {
  return useSubjectAbility('read', `column:${entityName}.${fieldName}`);
}

/**
 * API 호출 권한
 * @example useApiAbility('POST', '/users') → api:POST:/users ACCESS 체크
 */
export function useApiAbility(method: string, path: string): boolean {
  return useSubjectAbility('access', `api:${method}:${path}`);
}
```

#### 3.7.7 ConstantSyncService 구현

```typescript
// packages/service/src/constant-sync.service.ts

import {
  ADMIN_NAV_ITEMS,
  FEATURE_ITEMS,
  type NavItemConfig,
} from "@cocrepo/constant";
import { SubjectTypes } from "@cocrepo/prisma";

interface SubjectData {
  name: string;
  type: SubjectTypes;
  displayName: string;
  parentName: string | null;
}

@Injectable()
export class ConstantSyncService {
  constructor(private readonly subjectsRepository: SubjectsRepository) {}

  /**
   * @cocrepo/constant에서 Menu/Feature Subject를 동기화합니다.
   */
  async syncFromConstant(tenantId: string): Promise<SyncResult> {
    const result: SyncResult = { created: 0, updated: 0, skipped: 0 };

    // 1. Menu Subject 동기화
    const menuSubjects = this.flattenNavItems(ADMIN_NAV_ITEMS, SubjectTypes.Menu);
    await this.syncSubjects(menuSubjects, tenantId, result);

    // 2. Feature Subject 동기화
    const featureSubjects = this.parseFeatureItems(FEATURE_ITEMS);
    await this.syncSubjects(featureSubjects, tenantId, result);

    this.logger.log(
      `Constant 동기화 완료: 생성=${result.created}, 업데이트=${result.updated}, 스킵=${result.skipped}`
    );

    return result;
  }

  /**
   * NavItemConfig 트리를 플랫한 Subject 배열로 변환
   */
  private flattenNavItems(
    items: NavItemConfig[],
    type: SubjectTypes,
    parentName: string | null = null
  ): SubjectData[] {
    const result: SubjectData[] = [];

    for (const item of items) {
      result.push({
        name: item.subject,        // 'menu:dashboard'
        type,
        displayName: item.label,   // '대시보드'
        parentName,
      });

      if (item.children) {
        result.push(
          ...this.flattenNavItems(item.children, type, item.subject)
        );
      }
    }

    return result;
  }

  /**
   * Subject 배열을 DB에 동기화 (upsert)
   */
  private async syncSubjects(
    subjects: SubjectData[],
    tenantId: string,
    result: SyncResult
  ): Promise<void> {
    // 1단계: parentName → parentId 매핑을 위해 먼저 부모 없는 것들 처리
    const noParent = subjects.filter(s => !s.parentName);
    const withParent = subjects.filter(s => s.parentName);

    for (const subject of noParent) {
      await this.upsertSubject(subject, tenantId, null, result);
    }

    // 2단계: 부모가 있는 것들 처리
    for (const subject of withParent) {
      const parent = await this.subjectsRepository.findByName(subject.parentName!);
      await this.upsertSubject(subject, tenantId, parent?.id ?? null, result);
    }
  }

  private async upsertSubject(
    data: SubjectData,
    tenantId: string,
    parentId: string | null,
    result: SyncResult
  ): Promise<void> {
    const existing = await this.subjectsRepository.findByName(data.name);

    if (!existing) {
      await this.subjectsRepository.create({
        name: data.name,
        type: data.type,
        displayName: data.displayName,
        tenantId,
        parentId,
      });
      result.created++;
    } else if (existing.displayName !== data.displayName) {
      // displayName이 변경되었으면 업데이트 (constant가 우선)
      await this.subjectsRepository.updateById(existing.id, {
        displayName: data.displayName,
        parentId,
      });
      result.updated++;
    } else {
      result.skipped++;
    }
  }
}
```

#### 3.7.10 동기화 규칙 요약

| Source of Truth | Subject 타입 | 동기화 우선순위 | 비고 |
|-----------------|-------------|----------------|------|
| `@cocrepo/constant` | Menu | Constant 우선 | displayName 변경 시 덮어씀 |
| `@cocrepo/constant` | Feature | Constant 우선 | displayName 변경 시 덮어씀 |
| Prisma Schema | Entity | DB null이면 업데이트 | 관리자 오버라이드 유지 |
| Prisma Schema | Column | DB null이면 업데이트 | 관리자 오버라이드 유지 |

**차이점:**
- **Menu/Feature**: `@cocrepo/constant`가 항상 우선 (코드가 Source of Truth)
- **Entity/Column**: DB에 값이 있으면 유지 (관리자가 한글명을 변경했을 수 있음)

## 5. 백엔드 구현

### 5.1 CaslAbilityFactory

```typescript
// packages/be-common/src/casl/casl-ability.factory.ts
import { AbilityBuilder, createMongoAbility, MongoAbility } from '@casl/ability';

export type AppAbility = MongoAbility<[AbilityAction, AbilitySubject]>;

@Injectable()
export class CaslAbilityFactory {
  constructor(
    private readonly abilitiesRepository: AbilitiesRepository,
  ) {}

  async createForUser(user: UserDto): Promise<AppAbility> {
    const { can, cannot, build } = new AbilityBuilder<AppAbility>(
      createMongoAbility
    );

    // 1. Role 기반 Ability 조회 (기본 권한)
    const roleAbilities = await this.abilitiesRepository.findActiveByRoleId(
      user.roleId
    );

    // 2. User 기반 Ability 조회 (예외 권한)
    const userAbilities = await this.abilitiesRepository.findActiveByUserId(
      user.id
    );

    // 3. 병합 (Role 먼저, User가 덮어씀)
    const allAbilities = [...roleAbilities, ...userAbilities]
      .sort((a, b) => a.priority - b.priority);

    // 4. CASL Ability 빌드
    for (const ability of allAbilities) {
      const conditions = ability.conditions
        ? this.interpolateConditions(ability.conditions, user)
        : undefined;

      if (ability.inverted) {
        cannot(ability.action as AbilityAction, ability.subject, conditions);
      } else {
        can(ability.action as AbilityAction, ability.subject, ability.fields, conditions);
      }
    }

    return build();
  }

  private interpolateConditions(conditions: any, user: UserDto): any {
    const conditionStr = JSON.stringify(conditions);

    const variables: Record<string, string> = {
      '${user.id}': user.id,
      '${user.departmentId}': user.departmentId ?? '',
      '${user.spaceId}': user.tenants?.find(t => t.main)?.spaceId ?? '',
      '${user.role}': user.tenants?.find(t => t.main)?.role?.name ?? '',
    };

    let interpolated = conditionStr;
    for (const [key, value] of Object.entries(variables)) {
      interpolated = interpolated.replace(new RegExp(key.replace('$', '\\$'), 'g'), value);
    }

    return JSON.parse(interpolated);
  }
}
```

### 5.2 ABAC 가드 (선택적 적용)

```typescript
// packages/be-common/src/casl/casl-ability.guard.ts
@Injectable()
export class CaslAbilityGuard implements CanActivate {
  constructor(
    private reflector: Reflector,
    private caslAbilityFactory: CaslAbilityFactory,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const requiredAbilities = this.reflector.get<AbilityCheck[]>(
      CHECK_ABILITIES_KEY,
      context.getHandler(),
    );

    // ABAC 체크가 필요 없으면 통과
    if (!requiredAbilities || requiredAbilities.length === 0) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const ability = await this.caslAbilityFactory.createForUser(request.user);

    return requiredAbilities.every(check =>
      ability.can(check.action, check.subject)
    );
  }
}

// 데코레이터
export const CheckAbilities = (...abilities: AbilityCheck[]) =>
  SetMetadata(CHECK_ABILITIES_KEY, abilities);

interface AbilityCheck {
  action: AbilityAction;
  subject: AbilitySubject;
}
```

```typescript
  // ABAC 추가 적용 (조건부 접근)
  @Get(':id')
  @UseGuards(CaslAbilityGuard)
  @CheckAbilities({ action: 'read', subject: 'User' })
  async findOne(@Param('id') id: string, @CurrentUser() user: UserDto) {

    const targetUser = await this.usersService.findById(id);

    if (!ability.can('read', subject('User', targetUser))) {
      throw new ForbiddenException('이 사용자 정보에 접근할 수 없습니다');
    }

    return targetUser;
  }
}
```


### 10.2 스키마 변경 내용

```prisma
// ✅ Subject 모델 유지 (Column Subject 필드 가시성에 필요)
model Subject {
  id          String       @id @default(uuid())
  name        String       @unique  // "entity:User", "column:User.email"
  type        SubjectTypes @default(Entity)  // Menu, Feature, Entity, API, Column
  displayName String?      // Prisma @displayName에서 자동 동기화
  parentId    String?      // Column의 경우 Entity Subject 참조
  // ...
}

// ✅ Ability 모델 - Subject FK 참조
model Ability {
  id          String         @id @default(uuid())
  type        AbilityTypes   // CAN / CAN_NOT
  action      AbilityActions // READ, CREATE, UPDATE, DELETE, MANAGE
  roleId      String         // Role 기반 (기본)
  subjectId   String         // Subject 테이블 FK
  conditions  Json?          // 마스킹 패턴 등 추가 조건
  // ...

  subject     Subject        @relation(fields: [subjectId], references: [id])
}
```
