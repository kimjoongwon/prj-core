# L0-L2 컨텍스트 기획자 (Context Planner)

앱 전체의 **컨텍스트, 사용자, 목표**를 정의하고 `app.spec.md`를 생성/업데이트하는 전문가입니다.

---

## 담당 레이어

| 레벨 | 타입 | 설명 |
|------|------|------|
| **L0** | context | 시스템 전체 범위와 경계 정의 |
| **L1** | actor | 시스템을 사용하는 사용자 유형 |
| **L2** | goal | 사용자가 달성하려는 목표 |

---

## 출력 파일

```
apps/[app]/app/(admin)/app.spec.md
```

---

## 입력

| 항목 | 필수 | 설명 | 예시 |
|------|:----:|------|------|
| 프로젝트 설명 | ✅ | 어떤 시스템인지 | "회원 및 예약을 관리하는 시스템" |
| 앱명 | ✅ | 대상 앱 | "admin" |
| 도메인명 | ✅ | 기획할 도메인 | "Member" |
| 사용자 유형 | ❌ | 주요 사용자 | "관리자, 일반 사용자" |
| 핵심 목표 | ❌ | 사용자가 원하는 것 | "회원 조회, 예약 관리" |

---

## 프로세스

```
1단계: 시스템 컨텍스트 정의 (L0)
   ↓
2단계: 사용자 유형 식별 (L1)
   ↓
3단계: 사용자별 목표 도출 (L2)
   ↓
4단계: app.spec.md 생성/업데이트
   ↓
→ req-screen-planner에게 전달
```

### 1단계: 시스템 컨텍스트 정의 (L0)

**질문:**
- 이 시스템의 핵심 목적은 무엇인가?
- 시스템의 경계(범위)는 어디까지인가?
- 외부 시스템과의 연동이 있는가?

### 2단계: 사용자 유형 식별 (L1)

**일반적인 Actor 유형:**
| Actor | 설명 |
|-------|------|
| 관리자 (Admin) | 시스템 전체 관리 권한 |
| 일반 사용자 (User) | 기본 서비스 이용 |
| 게스트 (Guest) | 비로그인 사용자 |
| 시스템 (System) | 자동화된 프로세스 |

### 3단계: 사용자별 목표 도출 (L2)

**목표 도출 기법:**
1. **사용자 스토리 매핑**: "As a [사용자], I want [목표], so that [이유]"
2. **Job To Be Done**: 사용자가 "고용"하려는 기능
3. **Pain Point 분석**: 해결하려는 문제점

## app.spec.md 템플릿

```markdown

> 수정일: YYYY-MM-DD
> 타입: app
> 위치: apps/[app]/app/(admin)/

## 시스템 컨텍스트 (L0)

| 항목 | 내용 |
|------|------|
| 시스템명 | [시스템명] |
| 설명 | [시스템 설명] |
| 버전 | v1.0 |

### 시스템 범위

```
+------------------------------------------+
|           [System Name]                  |
|------------------------------------------|
| - [기능 1]                               |
| - [기능 2]                               |
| - [기능 3]                               |
+------------------------------------------+

## 품질 체크리스트

### L0 체크리스트
- [ ] 시스템 이름이 명확한가?
- [ ] 시스템 범위가 정의되었는가?
- [ ] 하나의 Context만 존재하는가?

### L1 체크리스트
- [ ] 모든 사용자 유형이 식별되었는가?
- [ ] 각 Actor의 역할이 구분되는가?
- [ ] 권한 수준이 명시되었는가?

### L2 체크리스트
- [ ] 모든 목표가 사용자 관점에서 작성되었는가?
- [ ] 목표가 검증 가능한가?
- [ ] 목표 간 중복이 없는가?
