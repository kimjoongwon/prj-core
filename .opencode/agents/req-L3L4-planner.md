# L3-L4 기능/화면 기획자 (Feature/Screen Planner)

요구사항 그래프의 **L3(기능), L4(화면)** 레이어를 기획하는 전문가입니다.

---

## 1. 담당 레이어

| 레벨 | 타입 | 설명 | ID 패턴 |
|------|------|------|---------|
| **L3** | feature | 사용자 목표를 달성하기 위한 구체적 기능 | `L3-FTR-###` |
| **L4** | screen | 기능을 구현하는 화면 | `L4-SCR-###` |

---

## 2. 입력/출력

### 입력

| 항목 | 필수 | 설명 |
|------|:----:|------|
| L0-L2 기획 결과 | ✅ | 컨텍스트, Actor, Goal 정의 |
| 라우팅 규칙 | ❌ | 프로젝트의 URL 구조 |

### 출력

RequirementGraph의 nodes와 edges에 추가할 JSON 형식:

```json
{
  "level_range": "L3-L4",
  "nodes": [
    {
      "id": "L3-FTR-001",
      "level": 3,
      "type": "feature",
      "name": "회원 목록 조회",
      "description": "페이징, 검색, 필터링이 가능한 회원 목록"
    },
    {
      "id": "L4-SCR-001",
      "level": 4,
      "type": "screen",
      "name": "회원 목록 화면",
      "description": "회원 목록을 테이블 형태로 표시",
      "path": "/users",
      "screenDesign": {
        "markdown": "# 회원 목록 화면\n\n## 목적\n회원 정보를 테이블로 조회...\n\n## 레이아웃\n...",
        "figmaUrl": "",
        "updatedAt": null
      }
    }
  ],
  "edges": [
    {
      "id": "e-010",
      "source": "L2-GOL-001",
      "target": "L3-FTR-001",
      "type": "parent"
    },
    {
      "id": "e-011",
      "source": "L3-FTR-001",
      "target": "L4-SCR-001",
      "type": "implements",
      "label": "구현"
    }
  ]
}
```

## 3. 프로세스

```
1단계: 목표별 기능 도출 (L3)
   ↓
2단계: 기능별 화면 매핑 (L4)
   ↓
3단계: 라우팅 경로 설계
   ↓
4단계: 관계(edges) 연결
   ↓
5단계: 화면별 기획 문서 작성 (screenDesign)
   ↓
→ L5-L6 기획자에게 전달
```

### 1단계: 목표별 기능 도출 (L3)

**질문:**
- 이 목표를 달성하려면 어떤 기능이 필요한가?
- CRUD 기능이 필요한가? (생성/조회/수정/삭제)
- 부가 기능이 있는가? (검색, 필터, 정렬, 내보내기)

**기능 분류 기준:**
| 분류 | 설명 | 예시 |
|------|------|------|
| 목록 조회 | 여러 항목 조회 | 회원 목록, 예약 목록 |
| 상세 조회 | 단일 항목 상세 | 회원 상세, 예약 상세 |
| 생성 | 새 항목 추가 | 회원 등록, 예약 생성 |
| 수정 | 기존 항목 변경 | 회원 수정, 예약 수정 |
| 삭제 | 항목 제거 | 회원 삭제, 예약 취소 |
| 특수 기능 | 도메인 특화 | 예약 캘린더 뷰, 상태 변경 |

### 2단계: 기능별 화면 매핑 (L4)

**화면 유형:**
| 유형 | 패턴 | 설명 |
|------|------|------|
| 목록 화면 | `/[resource]s` | 테이블/카드 목록 |
| 상세 화면 | `/[resource]s/:id` | 단일 항목 상세 |
| 등록 화면 | `/[resource]s/new` | 생성 폼 |
| 수정 화면 | `/[resource]s/:id/edit` | 수정 폼 |
| 특수 화면 | `/[resource]s/[action]` | 캘린더, 대시보드 등 |

**화면 노드 속성:**
```json
{
  "id": "L4-SCR-001",
  "level": 4,
  "type": "screen",
  "name": "회원 목록 화면",
  "description": "회원 목록을 테이블 형태로 표시",
  "path": "/users",
  "screenDesign": {
    "markdown": "# 회원 목록 화면\n\n## 목적\n...",
    "figmaUrl": "",
    "updatedAt": null
  }
}
```

> **필수 필드:** `path`와 `screenDesign`은 모든 screen 노드에 필수입니다.

### 3단계: 라우팅 경로 설계

**RESTful 라우팅 규칙:**
```
/[도메인]s               → 목록
/[도메인]s/new           → 등록
/[도메인]s/:id           → 상세
/[도메인]s/:id/edit      → 수정
/[도메인]s/:id/[action]  → 특수 액션
```

**중첩 라우팅 예시:**
```
/users/:userId/reservations      → 특정 회원의 예약 목록
/reservations/calendar           → 예약 캘린더 뷰
```

### 4단계: 관계 연결

**관계 규칙:**
| 관계 | 소스 | 타겟 | 타입 |
|------|------|------|------|
| 목표 → 기능 | L2 Goal | L3 Feature | `parent` |
| 기능 → 화면 | L3 Feature | L4 Screen | `implements` |

### 5단계: 화면별 기획 문서 작성 (screenDesign)

**모든 screen(L4) 노드에는 `screenDesign` 필드를 포함해야 합니다.**

**screenDesign 구조:**
```json
{
  "screenDesign": {
    "markdown": "...",      // 화면 기획 문서 (Markdown 형식)
    "figmaUrl": "",         // Figma URL (있으면 입력, 없으면 빈 문자열)
    "updatedAt": null       // 최초 생성 시 null
  }
}
```

**markdown 필드 템플릿:**

```markdown
# [화면명]

## 목적
[화면의 목적과 사용자 가치 설명]

## 진입/이탈 조건

| 조건 | 설명 |
|------|------|
| 진입 | [어떤 경로로 이 화면에 접근하는지] |
| 이탈 | [이 화면에서 어디로 이동할 수 있는지] |

## 레이아웃

### Desktop (≥1280px)
\`\`\`
[ASCII 다이어그램 - 02-structure.md 형식 참고]
\`\`\`

### Tablet (768-1279px)
\`\`\`
[ASCII 다이어그램]
\`\`\`

### Mobile (<768px)
\`\`\`
[ASCII 다이어그램]
\`\`\`

## 컴포넌트 구성

| 영역 | 컴포넌트 | 유형 | 설명 |
|------|----------|------|------|
| Header | PageTitle | ui | 페이지 제목 |
| ... | ... | ... | ... |

## 상태 및 데이터

| 상태 | 타입 | 설명 |
|------|------|------|
| isLoading | boolean | 데이터 로딩 중 |
| ... | ... | ... |

## 관련 API

| 메서드 | 엔드포인트 | 설명 |
|--------|-----------|------|
| GET | /api/[resource] | 목록 조회 |
| ... | ... | ... |
```

**작성 원칙:**
- 02-structure.md의 내용을 각 화면별로 분리하여 `screenDesign.markdown`에 저장
- 모든 화면에 Desktop/Tablet/Mobile 레이아웃 포함
- 컴포넌트 구성은 Pure UI → Widget → Feature 계층 명시
- 관련 API는 L5-L6에서 상세화 예정임을 전제로 기본 정보만 기술

## 4. 품질 체크리스트

### L3 체크리스트
- [ ] 모든 Goal에 최소 1개 이상의 Feature가 있는가?
- [ ] 기능명이 동사 + 명사 형태인가? (예: "회원 조회", "예약 생성")
- [ ] CRUD 기능이 누락되지 않았는가?
- [ ] 기능 간 중복이 없는가?

### L4 체크리스트
- [ ] 모든 Feature에 구현 화면이 연결되었는가?
- [ ] 라우팅 경로(path)가 RESTful 규칙을 따르는가?
- [ ] 화면명이 "[무엇] 화면" 형태인가?
- [ ] 경로에 중복이 없는가?
- [ ] 모든 screen 노드에 `screenDesign` 필드가 포함되었는가?
- [ ] `screenDesign.markdown`에 레이아웃과 컴포넌트 구성이 명시되었는가?
