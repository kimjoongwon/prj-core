# 01. 개요 및 기존 시스템 분석

## 1. 시스템 개요

### 1.1 오케스트레이션 시스템이란?

에이전트 오케스트레이션 시스템은 복잡한 개발 작업을 자동화하기 위해 여러 에이전트를 조율하고 관리하는 시스템입니다.

### 1.2 핵심 문제 해결

| 문제 | 해결 방안 |
|------|----------|
| 복잡한 워크플로우 관리 | 선언적 워크플로우 정의 |
| 에이전트 간 통신 복잡성 | 표준화된 인터페이스 및 프로토콜 |
| 에러 처리 및 롤백 | 자동화된 에러 핸들링 및 상태 관리 |
| 진행 상황 추적 | 실시간 상태 추적 및 PROGRESS.md 자동 업데이트 |

---

## 2. 기존 시스템 분석

### 2.1 기존 오케스트레이터 (orch-requirement)

**특징:**
- 수동 에이전트 호출 (Task 도구)
- 순차적 실행 (L0-L2 → L3-L4 → L5-L6 → L7-L8 → L9-L10)
- 기본적인 에러 처리
- PROGRESS.md 수동 업데이트

**한계:**
- 워크플로우가 하드코딩되어 있음
- 병렬 실행 불가
- 실패 시 재시도/롤백 어려움
- 상태 추적이 제한적

### 2.2 L0-L10 레이어 시스템

| 레이어 | 담당 에이전트 | 설명 |
|--------|--------------|------|
| L0-L2 | req-L0L2-planner | 컨텍스트/사용자/목표 |
| L3-L4 | req-L3L4-planner | 기능/화면 |
| L5-L6 | req-L5L6-planner | 인터랙션/API |
| L7-L8 | req-L7L8-planner | 데이터모델/컴포넌트 |
| L9-L10 | req-L9L10-planner | 로직/테스트 |

## 5. 핵심 개념

### 5.1 워크플로우 (Workflow)

에이전트 실행 순서 및 조건을 정의한 구조입니다.

```typescript
{
  id: "requirement-workflow",
  name: "요구사항 기획 워크플로우",
  steps: [
    {
      id: "l0l2",
      agent: "req-L0L2-planner",
      inputs: { /* ... */ },
      outputs: { /* ... */ },
    },
    {
      id: "l3l4",
      agent: "req-L3L4-planner",
      dependsOn: ["l0l2"],  // l0l2 완료 후 실행
    },
    // ...
  ]
}
```

### 5.2 오케스트레이션 컨텍스트 (OrchestrationContext)

워크플로우 실행에 필요한 모든 정보를 담는 컨텍스트입니다.

```typescript
{
  workflowId: "requirement-workflow",
  projectId: "project-alpha",
  appId: "admin-web",
  featureName: "Member",
  executionId: "exec-001",
  startTime: new Date(),
  steps: [
    {
      id: "l0l2",
      status: "completed",
      result: { /* ... */ },
    },
    // ...
  ],
}
```

### 5.3 에이전트 실행 상태 (AgentExecutionState)

각 에이전트의 실행 상태를 추적합니다.

| 상태 | 설명 |
|------|------|
| `pending` | 대기 중 |
| `running` | 실행 중 |
| `completed` | 완료 |
| `failed` | 실패 |
| `skipped` | 건너뜀 |
| `retrying` | 재시도 중 |
