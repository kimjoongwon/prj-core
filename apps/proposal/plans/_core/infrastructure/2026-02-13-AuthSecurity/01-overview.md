### 핵심 설계 원칙

1. **사용자 여정 우선**: 기능이 아닌, 사용자가 실제로 겪는 흐름 중심 설계
2. **조용한 실패**: 보안 정보 노출 방지 (이메일 존재 여부, 계정 상태 등)
3. **방어적 계층**: 프론트엔드 검증 + 백엔드 검증 이중 적용
4. **세션 일관성**: OIDC 세션과 앱 세션의 수명주기 동기화

## L1: 사용자 (Actor)

### 사용자 정의

| ID | 사용자 | 역할 | 핵심 여정 |
|----|--------|------|----------|
| AUTH-ACT-001 | 신규 사용자 | 모든 Role | 초대받고 첫 로그인, 비밀번호 설정 |
| AUTH-ACT-002 | 일반 사용자 | VIEW/MANAGE | 매일 로그인/로그아웃, 비밀번호 관리, 세션 확인 |
| AUTH-ACT-003 | 시스템 관리자 | FULL_ACCESS | 계정 보안 관리, 감사 로그, 세션 강제 종료 |

### 사용자 특성

#### AUTH-ACT-001: 신규 사용자
- **상황**: 관리자가 계정을 생성하고 임시 비밀번호를 전달받음
- **기대**: 첫 로그인 시 내 비밀번호로 변경할 수 있어야 함
- **불안**: "이 임시 비밀번호가 맞나?", "비밀번호 규칙이 뭐지?"

#### AUTH-ACT-002: 일반 사용자
- **상황**: 매일 업무 시작 시 로그인, 퇴근 시 로그아웃
- **기대**: 빠르고 안전하게 로그인, 문제 시 셀프서비스로 해결
- **불안**: "비밀번호를 잊었는데 어떡하지?", "내 계정이 다른 데서 쓰이고 있나?"

#### AUTH-ACT-003: 시스템 관리자
- **상황**: 보안 사고 대응, 계정 문제 해결, 정기 감사
- **기대**: 즉시 대응 가능한 도구, 명확한 로그, 일괄 처리
- **불안**: "누가 언제 무엇을 했는지 추적할 수 있나?"

## L2: 사용자 목표 (Goal) - 여정 기반

### 여정 1: 첫 접근과 온보딩

| ID | 목표 | Actor | 설명 |
|----|------|-------|------|
| AUTH-GOL-101 | 안전한 첫 로그인 | 신규 사용자 | 임시 비밀번호로 로그인 후 반드시 내 비밀번호로 변경 |

**사용자 흐름**:
```
관리자가 계정 생성 → 임시 비밀번호 이메일 발송
→ 사용자가 이메일 확인 → 로그인 페이지
→ 임시 비밀번호로 로그인 → 비밀번호 변경 강제 화면
→ 새 비밀번호 입력 (실시간 정책 검증) → 설정 완료
→ 정상 로그인 상태로 진입
```

### 여정 2: 일상 로그인

| ID | 목표 | Actor | 설명 |
|----|------|-------|------|
| AUTH-GOL-201 | 빠른 로그인 | 일반 사용자 | 이메일/비밀번호로 로그인, Remember Me |
| AUTH-GOL-202 | 실패 시 명확한 안내 | 일반 사용자 | 남은 시도 횟수, 잠금 상태, 해결 방법 안내 |

**사용자 흐름 (성공)**:
```
로그인 페이지 → 이메일/비밀번호 입력 → [Remember Me 체크]
→ 로그인 성공 → Space 선택 → 대시보드
```

**사용자 흐름 (실패)**:
```
비밀번호 오류 → "이메일 또는 비밀번호가 올바르지 않습니다 (남은 시도: 4/5)"
→ 5회 실패 → "계정이 일시 잠겼습니다. 15분 후 다시 시도하세요"
→ 10회 실패 → "계정이 잠겼습니다. 관리자에게 문의하거나 비밀번호를 재설정하세요"
                 [비밀번호 재설정] [관리자 문의]
```

### 여정 3: 세션 유지와 만료

| ID | 목표 | Actor | 설명 |
|----|------|-------|------|
| AUTH-GOL-301 | 끊김 없는 작업 | 일반 사용자 | 작업 중 토큰 만료 시 자동 갱신, 사용자가 인지 못함 |
| AUTH-GOL-302 | 부드러운 재로그인 | 일반 사용자 | 세션 완전 만료 시 안내 후 로그인 페이지 이동 |

**사용자 흐름**:
```

  → 갱신 성공 → 원래 요청 재시도 (사용자 인지 못함)
  → 갱신 실패 → "세션이 만료되었습니다. 다시 로그인해주세요" 토스트
               → 로그인 페이지로 이동
```

### 여정 4: 로그아웃

| ID | 목표 | Actor | 설명 |
|----|------|-------|------|
| AUTH-GOL-401 | 완전한 로그아웃 | 일반 사용자 | 현재 기기에서 완전히 로그아웃 (OIDC + 앱 세션 모두) |
| AUTH-GOL-402 | 모든 기기 로그아웃 | 일반 사용자 | 모든 기기에서 동시에 로그아웃 |

**사용자 흐름 (현재 기기)**:
```
헤더 드롭다운 → "로그아웃" 클릭
→ IDP 토큰 무효화 (Revocation)
→ OIDC 세션 종료 (End Session)
→ Access Token 블랙리스트 등록
→ Refresh Token 삭제
→ 쿠키 삭제 (accessToken, refreshToken, tenantId, workspaceId)
→ 로컬스토리지 정리 (PersistStore)
→ 로그인 페이지
```

**사용자 흐름 (모든 기기)**:
```
내 세션 관리 → "모든 다른 기기에서 로그아웃" 클릭
→ 확인 다이얼로그 → 모든 OIDC Grant 폐기
→ 현재 세션 제외 모든 Refresh Token 삭제
→ "다른 기기에서 모두 로그아웃되었습니다" 확인
```

### 여정 5: 비밀번호 분실과 재설정

| ID | 목표 | Actor | 설명 |
|----|------|-------|------|
| AUTH-GOL-501 | 셀프 비밀번호 재설정 | 일반 사용자 | 관리자 도움 없이 이메일로 비밀번호 재설정 |

**사용자 흐름**:
```
로그인 페이지 → "비밀번호를 잊으셨나요?" 클릭
→ 이메일 입력 → 제출
→ "입력하신 이메일로 재설정 링크를 발송했습니다" (이메일 존재 여부 무관)
→ 이메일 확인 → 재설정 링크 클릭 (30분 유효)
→ 새 비밀번호 입력 (실시간 정책 검증 + 이전 비밀번호 재사용 방지)
→ "비밀번호가 변경되었습니다. 다시 로그인해주세요"
→ 모든 세션 자동 무효화 → 로그인 페이지
```

### 구현 범위 (Phase)

| Phase | 여정 | 설명 |
|-------|------|------|
| **Phase 1** | 여정 2, 4 | 로그인 강화 (실패 제한, 잠금, 감사 로그) + 로그아웃 완성 |
| **Phase 2** | 여정 5, 6 | 비밀번호 재설정 + 비밀번호 변경 |
| **Phase 3** | 여정 8, 9 | 내 세션 관리 + 관리자 보안 관리 + 감사 로그 |
| **Phase 4** | 여정 1, 7 | 첫 로그인 비밀번호 강제 변경 + 비밀번호 만료 |
