Design Research: 예약 화면

TL;DR

운동/클래스 예약 화면은 "탐색 화면"과 "예약 확정 화면"을 분리하는 편이 가장 안정적입니다. 첫 화면에서는 수업 카드, 날짜 스트립, 잔여석/마감/대기 상태를 한눈에 보여주고, 상세에서는 날짜-시간 선택과 취소 정책, 수업권 차감, 캘린더 추가까지 확정 전후 정보를 명확히 고정해야 합니다.

하이파이브와 F45는 빠른 수업 예약과 대기 알림이 강하고, 네이버예약은 업종별 예약 유형과 결제/알림/관리까지 연결하는 범용성이 강합니다.

Recommendations / Next Steps

  1. 첫 화면은 수업 피드 + 날짜 스트립으로 시작 - 사용자는 예약 전에 "오늘 갈 수 있는 수업"을 먼저 봅니다.
  2. 시간 선택은 예약 슬롯 카드로 처리 - 예약 시간은 운영자가 만든 재고이므로 가능한 시간, 마감, 대기, 잔여석을 슬롯 단위로 보여줘야 합니다.
  3. 확정 직전에는 정책을 한 장에 요약 - 노쇼, 취소 가능 시간, 수업권 차감 조건을 확인시킨 뒤 예약을 완료합니다.
  4. 마감 상태는 대기/알림 액션으로 전환 - 마감 카드를 숨기지 말고 "왜 못 하는지"와 "다음 액션"을 같이 보여줍니다.
+--------------------------------+
| 센터명 / 지점 변경        알림 |
| 남은 수업권 8회  만료 D-23     |
+--------------------------------+
| 5/7 오늘 | 5/8 금 | 5/9 토 ... |
+--------------------------------+
| [전체] [근력] [유산소] [강사] |
+--------------------------------+
| 08:10  하체 집중  4/10석       |
| 강사 김OO  50분        [예약] |
| 09:10  하체 집중  마감         |
| 빈자리 알림 가능       [대기] |
+--------------------------------+

Key Examples

Patterns

  • 날짜는 캘린더보다 먼저 요일 스트립을 노출: 근미래 예약은 상단 요일 스트립이 빠릅니다.
  • 수업 카드는 정보 밀도가 높아야 함: 시간, 수업명, 강사, 지점, 난이도, 잔여석, 예약 상태가 카드 안에 있어야 합니다.
  • 예약 가능/마감/대기 상태를 같은 컴포넌트에서 표현: 숨김보다 상태 노출이 낫습니다.
  • 확정 CTA는 화면 하단 고정: 선택 내용 요약과 CTA 활성화가 함께 움직여야 합니다.
  • 예약 후 화면은 관리 화면의 시작점: 캘린더 추가, 변경, 취소, 문의, 수업권 상태를 바로 제공합니다.

Anti-Patterns

  • 연속형 시간 피커만 제공하기
  • 마감 수업 숨기기
  • 정책을 예약 후에만 고지하기
  • 수업권 잔여 횟수와 만료일 숨기기
  • 지점, 강사, 카테고리, 시간대 필터를 깊은 메뉴에 감추기

Unique Angles

하이파이브는 수업권 잔여 횟수, 예약 대기, 수업 알림을 한 앱에서 처리한다는 회원용 예약 감각이 강합니다.

F45는 리스트에서 빠르게 예약하되 상세에서 수업의 의미와 지점 정보를 이해하게 합니다.

네이버예약은 일반형, 뷰티형, 병의원형, 회차형, 시작-종료시간 선택형처럼 예약 모델을 다르게 둡니다.

Resy/Spring Health는 확정 전 정책 고지를 통해 취소/노쇼 리스크를 명확히 합니다.

Findings

1. 예약 화면의 핵심은 "예약 가능한 것만 빠르게 찾기"입니다

하이파이브와 F45는 사용자가 특정 수업을 이미 알고 들어온다고 가정합니다. 그래서 첫 화면부터 날짜별 수업 리스트를 보여주고, 상세한 마케팅 설명보다 예약 가능한 시간과 버튼을 앞세웁니다.

2. 네이버예약식 범용성은 정보 구조에 참고할 가치가 있습니다

피트니스에서도 일반 수업 예약, PT 상담, 체험 수업, 바디스캔, 공간/기구 예약은 서로 다른 시간 모델을 갖습니다. UI는 하나의 예약 모듈로 보이되 내부 데이터는 분리되어야 합니다.

3. 수업형 예약은 "정원"과 "대기"가 일반 예약보다 중요합니다

클래스 예약에서는 빈자리 알림, 대기 등록, 마감 임박, 취소 가능 시간, 노쇼 정책이 conversion만큼 중요합니다.

4. 확정 후에는 캘린더와 알림이 신뢰를 완성합니다

예약 완료 후 이메일 발송, 캘린더 추가, 대시보드 복귀를 제공하면 사용자는 예약 상태를 더 확실히 인지합니다.

Design Direction

  • Mobile-first: 회원용 예약 화면은 모바일 우선. 데스크톱은 관리/운영 화면에 더 적합합니다.
  • 권장 컴포넌트: DateStrip, ClassSessionCard, SlotPickerSheet, BookingPolicySheet, BookingConfirmationPanel, PassBalanceBadge, WaitlistButton.
  • 추천 상태값: AVAILABLE, FEW_LEFT, FULL, WAITLIST_OPEN, BOOKING_CLOSED, RESERVED, CANCELED.
